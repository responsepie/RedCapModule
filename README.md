# ResponsePie for REDCap

> **Development prerelease:** `v0.1.0` must be validated in a staging REDCap
> environment before production use.

This REDCap External Module loads ResponsePie on REDCap survey pages in an
enabled project. It uses the `redcap_survey_page_top` hook; it does not access
REDCap records, the REDCap database, or the REDCap API.

## Requirements

- REDCap Standard 13.7.0 or later, or REDCap LTS 13.7.3 or later
- PHP 7.2 or later
- REDCap External Module Framework 14
- Browser access to `https://studies.surveyproctor.com`

## Embed-code contract

ResponsePie supplies a complete, project-specific, one-line script element.
The researcher pastes that complete generated line into the module setting. The
`data-study-token` is a browser-visible, limited-scope study identifier needed
by the client script; it is not a password, API key, or other secret
credential. Nevertheless, use only the token generated for the intended
project.

Before output, the module requires exactly one empty external `<script>` tag,
an HTTPS URL on the exact host `studies.surveyproctor.com`, a JavaScript path
under `/static/take-redcap/`, and a nonempty bounded study token. Optional
SHA-384 integrity metadata and `crossorigin="anonymous"` are validated and
preserved. The module rejects inline JavaScript, extra tags and attributes,
malformed URLs, alternate hosts, ports, credentials, fragments, query strings,
and invalid integrity metadata. It never prints the configured HTML directly;
it reconstructs a tag from escaped, validated values. Invalid configuration
therefore produces no script tag.

## Administrator installation

1. Obtain `response_pie_redcap_v0.1.0.zip` from the reviewed prerelease
   artifact.
2. Extract it so REDCap's `modules` directory contains the folder
   `response_pie_redcap_v0.1.0` (without another parent folder).
3. In the REDCap Control Center, open **Manage External Modules** and enable
   **ResponsePie for REDCap**.
4. Enable the module in a staging project before approving production use.

## Researcher configuration

1. In the project, enable the participant-facing instruments as surveys.
2. Follow the ResponsePie workflow for the intended REDCap project.
3. Copy the complete, one-line embed code generated by ResponsePie. It must
   include the project-specific `data-study-token`; do not paste only its URL.
4. In REDCap, open **External Modules** or **Manage External Modules**, enable
   **ResponsePie for REDCap**, and select **Configure**.
5. Paste the complete line into **Complete ResponsePie one-line JavaScript
   embed code** and save.
6. Validate each relevant REDCap survey page in staging.

The setting applies to REDCap survey pages in the enabled project. The module
does not distinguish public survey links from other participant-facing survey
links provided to the hook.

## Browser verification

1. Open a staging REDCap survey page using the participant-facing link.
2. Open browser developer tools and select **Network**.
3. Reload the page and confirm one `.js` request to
   `studies.surveyproctor.com/static/take-redcap/` succeeds.
4. In **Elements**, confirm the script has the expected escaped
   `data-study-token` and, when generated, integrity and crossorigin values.
5. Complete the staging validation workflow and confirm expected ResponsePie
   behavior. Also verify project-management and data-entry pages do not load
   the script.

## Content Security Policy

An institutional Content Security Policy (CSP) may block the script even when
module configuration is valid. Administrators should narrowly allow
`https://studies.surveyproctor.com` in the applicable `script-src` directive
and any ResponsePie-documented connection directives. Do not use a broad
wildcard or enable `unsafe-inline` for this module. Browser console and Network
errors can identify a blocked directive. Coordinate CSP changes with the
institutional security team and validate them in staging.

## Upgrade

1. Back up the current module folder and record its project configuration.
2. Review the target version's notes and build or obtain its versioned ZIP.
3. Extract the new version as a separate versioned folder under `modules`.
4. Upgrade through **Manage External Modules**, retaining the complete embed
   line in `rp-embed-code`.
5. Repeat browser verification in staging before production rollout. Do not
   overwrite an existing version folder in place.

## Rollback

1. Disable the new module version for affected projects.
2. In **Manage External Modules**, select the previously installed version and
   restore the recorded project setting if REDCap does not retain it.
3. Repeat browser verification and confirm only the intended prior script is
   loaded.
4. If no validated version is available, leave the module disabled; invalid or
   absent configuration safely emits nothing.

## Reproducible package

From the repository root, run:

```sh
./scripts/package.sh
```

The script creates `dist/response_pie_redcap_v0.1.0.zip`. Its only entries are
the install folder `response_pie_redcap_v0.1.0/` containing `config.json`,
`ResponsePieRedcap.php`, `README.md`, and `LICENSE`. Tests, Git metadata,
development files, and extra parent directories are excluded.

## Development checks

```sh
php -r 'json_decode(file_get_contents("config.json"), true, 512, JSON_THROW_ON_ERROR);'
php -l ResponsePieRedcap.php
php tests/run.php
./scripts/package.sh
unzip -Z1 dist/response_pie_redcap_v0.1.0.zip
```

The production generator's exact output was not available while preparing this
prerelease, so no generated embed line has been copied into this repository or
represented as production output. Matching a real ResponsePie-generated line,
with its token redacted before recording any test fixture, remains a required
staging test before production use.

## Support
